# PCL YYH 性能优化记录（2026-10-20）

本次在 `c6190699ee6d7b21cb132ea51d1b03efe4c8d662` 基线上优化启动器的动画、列表、定时刷新和任务进度处理，保持 Minecraft 1.20.1 + Forge 的 Java 17 与保守 JVM 默认设置。

## 完成的修改

- 删除“始终验证证书”控件、配置键、强制配置分支、启动调用及自定义证书回调。HTTPS 继续使用 .NET 默认验证；测试中保留旧名称以防功能回归。
- 动画由常驻线程轮询改为 WPF 渲染帧驱动，无动画时解除订阅。隐藏或最小化时保留按需的 100 ms 回退计时，保证延迟操作与退出回调可以完成。
- 每帧只获取一次动画组快照，替换原先对字典反复按索引枚举的处理；保留同名替换、取消和顺序回调行为。
- 列表由逐元素监听布局改为每个滚动容器统一检查，合并重复调度。可见控件创建按约 8 ms 的预算分散到后续界面调度，初始化只执行一次并释放工厂闭包。
- 内存设置页仅在加载且可见时刷新。界面读取 Mod 数量使用后台缓存，最多每 5 秒更新；实际启动的工作线程等待新扫描，避免使用陈旧计数。缓存最多保留 128 个目录。
- 主时钟使用后台优先级的 DispatcherTimer，减少工作线程与界面线程的同步等待。任务栏进度在无任务时直接返回，一轮仅生成一次任务快照并统计一次状态。
- 清理约 60 处空 XML 文档、被注释的示例控件与调试语句，删除失效的更新残留清理、动画诊断计数和空的强制配置表。保留解释兼容性、行为和授权的必要注释。

## 实测

同机、Release、独立进程，从不带相邻项目 DLL 的单 EXE 加载相同动画压力场景。旧版使用上述基线，新版使用本次最终构建。

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 1000 个延迟动画组执行 120 次、每次推进 16 ms（预热 5 次后计时） | 256.927 ms | 4.854 ms |
| 无动画时，2 秒内动画模块主动投递的界面任务 | 129 次 | 0 次 |

该次压力场景的动画遍历耗时约减少 98.1%。这不是整个启动器的速度倍数，也不代表 Minecraft 帧率、下载速度或真实整合包启动速度的提升。结果会随机器、系统负载和活动动画数量变化；本次没有测量完整游戏游玩帧率或端到端启动时间。

可复现工具位于 `src/Tests/Performance/`，只隔离执行动画模块，避免启动真实下载或登录：

```powershell
dotnet build ./src/Tests/Performance/Performance.csproj -c Release
& ./src/Tests/Performance/bin/Release/net48/Performance.exe '待测单文件EXE的绝对路径'
```
